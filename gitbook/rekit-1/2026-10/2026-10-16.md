## 첫 매물 6개 입력과 데이터 검증 문제

운영 DB에 라셀르 4도어 45박스 냉장고, 매직쎸븐 식기세척기, 다이나믹 제빙기, 린나이 22L 튀김기, 그랜드우성 테이블냉장고 900, 엔터팩 실링기 6개를 SQL로 입력했다. 가격은 350,000~~1,200,000원, 정가는 700,000~~3,500,000원으로 입력했고, 추정값은 별도로 표시했다.

목록이 0건이고 관리자 목록이 500을 반환한 원인을 확인했다.

| 입력 값        | 문제                                          | 결과            |
| ----------- | ------------------------------------------- | ------------- |
| 판매 상태 “판매중” | 목록은 영문 `ACTIVE`만 조회                         | 목록에서 제외       |
| 한글 카테고리     | 카테고리는 `REFRIGERATOR`, `KITCHEN` 같은 영문 코드 사용 | 카테고리 탭에서 제외   |
| 등급 “S”      | 허용 등급은 A·B·C                                | 관리자 목록 전체 500 |

상품 목록 API는 0건을 반환했고, 운영 로그에는 등급 값 `S`를 처리하지 못한 오류가 남았다. 비활성 상품 1개만 조회하는 요청은 200으로 응답했다.

상태·등급 필드에 DB 허용 값 검사(CHECK 제약)가 없어서 SQL 입력을 우회할 수 있는 상태였다. 잘못된 행을 조회에서 건너뛰는 대신 DB 단계에서 차단하는 방향을 후속 작업으로 남겼다. SQL 실행 뒤 실제 정정 여부는 기록으로 확인하지 못했다.

운영 로그는 컨테이너 재생성 시 사라지고 UTC로 기록되며, 당시에는 크기 제한도 없었다. 로그 크기 제한은 이후 [11.05 일지](../2026-11/2026-11-05.md)에서 반영했다.

## 퀵계좌이체

결제수단 목록은 토스 결제 위젯 내부 설정이므로 코드에서 퀵계좌이체 항목만 제거할 수 없었다. 테스트·운영 토스 상점 관리 화면에서 각각 비활성화해야 한다. 결제창이 열리지 않은 원인은 당시 확인하지 못했고, 계약 또는 활성화 상태를 점검해야 한다.

## 방치 주문과 이중 판매 방지

결제창을 닫으면 주문 생성 시 차감한 재고가 결제대기 주문에 묶였다. 다시 주문하면 새 주문 생성이 재고 부족으로 실패했고, 기존 30분 만료 처리는 주문 상세 조회에만 연결돼 있었다.

승인 처리가 주문을 잠그지 않는 동안 취소·만료 처리가 재고를 복구하면, 이후 승인이 주문을 결제완료로 바꿔 같은 상품을 다시 팔 수 있었다. 이 경합은 [07.10 일지](../2026-07/2026-07-10.md)에서 남긴 문제였다.

다음 규칙으로 처리했다.

| 상황                     | 처리                                       |
| ---------------------- | ---------------------------------------- |
| 결제창 닫기·인증 실패·결제창 열기 실패 | 다음 주문 전 이전 결제대기 주문을 정리하고, 화면에서도 즉시 취소 시도 |
| 탭 종료·브라우저 종료           | 재주문 시 정리, 남은 주문은 주기 작업으로 정리              |
| 승인 성공 후 응답 유실          | 취소 전 토스에 주문번호로 상태 조회, 완료면 결제 확정          |
| 승인과 취소·만료 동시 실행        | 주문 다음 결제 순서로 행 잠금                        |
| 이미 취소된 주문의 승인 웹훅       | 전액 자동 환불과 오류 기록                          |
| 토스 상태 조회 실패            | 주문을 취소하지 않고 다음 정리 시점으로 보류                |
| 여러 서버의 정리 작업 동시 실행     | 잠긴 주문을 건너뛰어 분할 처리                        |

결제 확정과 웹훅 처리에서 주문을 먼저 잠그고 결제를 잠그도록 통일했다. 취소된 주문의 완료 웹훅은 자동 환불하고, 환불 결과를 알 수 없으면 오류로 응답해 토스가 웹훅을 재시도하게 했다.

새 주문 생성 전에는 해당 사용자의 결제대기 주문을 토스 상태 확인 후 정리한다. 30분이 지난 주문은 2분 간격의 작업이 처리한다. 한 번에 최대 50건을 오래된 순서로 처리하고, 다른 작업이 잠근 주문은 건너뛴다. 간격 기본값은 120초이며 0이면 비활성화한다.

테스트는 승인·취소 경합 재현, 재주문 오류 재현, 정리 작업 3개 동시 실행, 자동 환불을 포함했다. 동시 정리 작업에서도 재고를 정확히 5개만 복구하는 것을 확인했다.

## 화면 보조 처리

주문서는 결제창을 열기 전에 실패하면 생성한 주문을 취소한다. 취소 실패는 서버 정리 작업이 처리하도록 화면에서 별도 오류를 내지 않았다.

결제 실패 화면은 주문 상태가 결제대기일 때만 취소한다. 결제가 끝난 주문에서 뒤로 가기로 이 화면이 열려 환불되는 일을 막기 위해서다.

승인 결과가 불확실한 연결 끊김·502·503·504 응답은 1.5초, 3초, 5초 간격으로 최대 세 번 재시도한다. 10월 2일에 추가한 중복 방지 키가 있어 재시도가 가능하다. 이후에도 실패하면 주문 상태를 조회해 결제대기·취소가 아닌 경우 완료 화면으로 이동한다.
