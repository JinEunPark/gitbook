# 06.27 · 찜 연결, 상품 묶음 조회, 검색을 서버로

관심상품을 서버에 연결하고, 장바구니·찜·주문서의 상품 조회를 묶음 조회로 변경했다. 검색도 서버 검색으로 이전했다.

| 작업                                 | 근거 커밋           |
| ---------------------------------- | --------------- |
| `POST /products/bulk`, 대표 사진 1장 조회 | `f53aba2` 16:10 |
| 관심상품, 묶음 조회, 검색 연결                 | `32916f4` 16:10 |

## 상품 묶음 조회

`POST /products/bulk`는 상품 ID 1\~100개를 받고 존재하는 상품만 반환한다. 반환 순서는 보장하지 않는다. 목록·신상품·묶음 조회는 카드에 필요한 대표 사진(`sort_order == 0`)만 읽도록 변경했고, 상세 조회는 전체 사진을 유지했다.

{% hint style="warning" %}
**확인된 제약**: 묶음 조회는 판매 상태를 검증하지 않아 숨긴 상품도 ID를 알면 조회될 수 있다.
{% endhint %}

## 관심상품과 가짜 상품 제거

비로그인 관심상품은 브라우저에 저장하고, 로그인하면 서버에 없는 항목만 `POST /favorites`로 추가한 뒤 브라우저 저장을 제거한다. 목록 변경 시 필요한 상품만 묶음 조회한다. 서버 API에 맞춰 구현해 장바구니의 합치기 문제와 달리 동작한다.

상품 스토어에서 가짜 상품 8개를 제거하고 `fetchById`, `fetchByIds`를 추가했다. 관리자 상품·매출 화면은 여전히 가짜 데이터 파일을 직접 사용한다. 품절 상태는 서버의 `SOLD_OUT`에 맞췄다.

## 검색과 상세 화면

모바일 검색은 300ms 후 최대 20개, PC 드롭다운은 200ms 후 최대 5개를 서버에 요청한다. 최근·인기 검색어는 브라우저에 유지한다. 모바일 상세 하단 버튼은 `--rekit-tab-bar-height`와 `env(safe-area-inset-bottom)`을 사용해 기기 하단 영역을 피하도록 수정했다.

{% hint style="warning" %}
**확인된 제약**: 검색은 debounce만 적용되어 이전 요청의 늦은 응답이 최신 검색 결과를 덮어쓸 수 있다.
{% endhint %}
