## 결제 완료 메일과 가짜 결제 모듈

`POST /payments/confirm`이 승인되면 주문자 이메일로 주문번호, 결제금액, 결제수단을 담은 완료 메일을 백그라운드에서 발송하도록 추가했다. 주문자 이메일이 없으면 메일을 보내지 않는다.

개발 환경에서는 `FakePaymentGateway`를 선택할 수 있게 했다. 가짜 결제는 개발카드, `0000`, `FAKE-APPROVAL`로 성공 응답을 만들고 웹훅 서명 검증도 통과시킨다. `use_fake_pg` 설정으로 전환하며, 설정 예시는 운영에서 false를 유지하도록 명시했다. 토스 비밀키 설정도 추가했다.

{% hint style="warning" %}
**확인된 제약**: 결제 메일 제목과 본문에 이전 서비스명 `Rekle`이 남아 있다.
{% endhint %}

## 이메일 인증 회원가입

가입을 코드 발송 → 코드 검증 → 가입의 세 요청으로 구성했다.

1. `POST /auth/email/send-verification`은 6자리 코드를 Redis에 10분 보관하고, 같은 이메일에는 1분당 한 번만 발송한다.
2. `POST /auth/email/verify-code`는 코드를 검증한 뒤 일회용으로 삭제하고, 15분짜리 이메일 확인 JWT를 발급한다.
3. `POST /auth/sign-up`은 이메일 대신 `verifiedToken`을 받고, 가입 후 로그인 토큰과 refresh 쿠키를 발급한다.

Redis 연결은 프로세스에서 재사용하며, 테스트에서는 `FakeRedis`를 사용한다.

{% hint style="warning" %}
**확인된 제약**

* 코드 확인 시도 횟수 제한이 없다.
* 발송 제한은 이메일 단위여서 한 IP의 다수 이메일 발송을 막지 못한다.
* 프론트는 다음 날까지 이전 가입 요청 형식을 사용해, 화면 수정 전에는 가입이 실패했다.
{% endhint %}

## HTML 인증 메일

`EmailSender.send(html_body=...)`를 추가해 텍스트와 HTML 본문을 함께 보낸다. 인증 메일은 Gmail, Apple Mail, Outlook 호환을 위해 table 레이아웃과 인라인 스타일로 작성했다.
