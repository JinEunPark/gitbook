# 05.07 · 비밀번호 찾기, 메일 발송, 로그인 확인

### 이날을 한 문단으로

서버만 만진 날이다. 전날 만든 회원가입·로그인을 다듬으면서 "가입하면 바로 로그인"을 없애고 가입과 로그인을 나눴다. 그러다 서버가 요청을 처리하고도 DB 에 저장을 확정하지 않아서, 가입은 성공했다고 답하는데 회원이 실제로는 남지 않는 큰 구멍을 찾아 고쳤다. 그 위에 아이디 찾기(메일로 보내기), 비밀번호 찾기(임시 비밀번호를 메일로 보내고 로그인하면 비밀번호부터 바꾸게 함), 비밀번호 변경을 만들고, 메일을 보내는 부분과 "로그인한 사람만 쓸 수 있는 기능"을 막는 검사 장치를 붙였다. 입력이 틀렸을 때 나오는 안내도 한국어 문장으로 바꿨고 테스트는 102개가 됐다.

### 1. 가입과 로그인 나누기

전날에는 가입하자마자 화면을 그릴 수 있게 가입 응답에 회원 정보와 출입증을 같이 줬다. 이날 아침 이걸 되돌려서 가입하면 회원 정보만 돌려주고 출입증과 쿠키는 주지 않게 했다. 출입증은 이제 로그인으로만 받는다. 사용자 입장에서는 가입을 마치면 로그인 화면으로 가서 한 번 더 로그인하는 흐름이 된다. 테스트 이름도 "가입하면 출입증을 준다"에서 "가입하면 회원을 만들고 돌려준다"로 바꿨다.

같이 정리한 것도 있다. DB 회원 정보를 응답 모양으로 옮길 때 칸마다 손으로 옮겨 적던 코드를 한 줄 자동 변환으로 바꿨고, "본인 확인 여부"는 회원 모델이 스스로 계산하게 옮겼다. 전날 테스트 준비 파일에만 넣었던 "시작할 때 모든 DB 모델 미리 불러오기"를 서버 시작 파일에도 넣었다. 모델끼리 이름으로만 이어 두었기 때문에, 서버를 실제로 띄워 처음 DB 를 읽을 때 연결을 못 찾는 문제를 막으려는 것이다. 시간 함수 표기와 줄바꿈도 코드 검사 규칙에 맞게 고쳤다.

### 3. 아이디 찾기, 비밀번호 찾기, 비밀번호 변경

회원이 아이디나 비밀번호를 잊었을 때 쓸 기능을 만들었다. 아이디 찾기는 가입한 이메일을 넣으면 화면에 아이디를 보여 주지 않고 그 메일함으로 보낸다. 비밀번호 찾기는 아이디와 이메일이 둘 다 맞으면 16자 임시 비밀번호를 만들어 메일로 보내고, 그 임시 비밀번호로 로그인하면 비밀번호를 바꾸기 전까지 다른 기능을 쓸 수 없게 했다. 원래 서버 명세서에는 "30분짜리 1회용 재설정 링크를 메일로 보내는" 방식과 그 링크용 재설정 기능이 있었는데, 이걸 지우고 임시 비밀번호 방식으로 바꿨다.

| 기능          | 보내는 것           | 돌려받는 것                 | 하는 일                                              |
| ----------- | --------------- | ---------------------- | ------------------------------------------------- |
| 아이디 찾기      | 이메일             | "보냈음"                  | 가입한 이메일이면 그 메일함으로 아이디를 보낸다                        |
| 비밀번호 찾기     | 로그인 아이디 + 이메일   | "보냈음" + 가린 이메일         | 둘 다 맞으면 임시 비밀번호를 만들고 메일로 보낸 뒤 "비밀번호 바꿔야 함" 표시를 켠다 |
| 비밀번호 변경     | 지금 비밀번호, 새 비밀번호 | 없음(204)                | 지금 비밀번호를 확인하고 바꾼 뒤 표시를 끈다                         |
| 로그인, 로그인 연장 | (기존과 같음)        | 응답에 "비밀번호 바꿔야 함" 여부 추가 | 켜져 있으면 화면이 비밀번호 변경 화면으로 보낸다                       |

임시 비밀번호로 로그인하면 출입증과 함께 "비밀번호 바꿔야 함"이 켜진 채로 응답이 온다. 이 상태에서 다른 기능을 부르면 "비밀번호 변경 필요(403)"로 거절되고, 비밀번호 변경 기능만 통과된다. 새 비밀번호로 바꾸면 표시가 꺼지고 그때부터 평소처럼 쓸 수 있다.

남이 이 기능으로 어떤 아이디·이메일이 가입돼 있는지 알아내지 못하게 하는 장치는 일관되게 넣었다. 아이디 찾기는 가입하지 않은 이메일이어도 똑같이 "보냈음"이라고 답한다. 비밀번호 찾기도 아이디와 이메일이 안 맞아도 같은 답을 하고, 함께 돌려주는 가린 이메일은 서버가 찾아낸 값이 아니라 사용자가 입력한 값을 그대로 가린 것이다(앞 1/3 만 보여 줌, 예: `ab****@…`). 안 맞을 때 업무 규칙은 에러를 내지 않고 조용히 끝난다.

임시 비밀번호는 영문 대소문자와 숫자 62글자 중에서 16자를 무작위로 뽑는다(경우의 수 약 4.8×10²⁸). 우연히 영문만 또는 숫자만 나오면(약 0.046%) 다시 뽑는다. 비밀번호 규칙 검사는 하나로 뽑아서 가입, 비밀번호 변경, 임시 비밀번호 만들기 세 곳이 같이 쓰게 했다. 규칙을 바꿀 때 한 곳만 바뀌어 서로 몰래 어긋나는 일을 막으려는 것이다.

{% hint style="warning" %}
**당시 남은 위험**

* 임시 비밀번호를 발급하면 그 자리에서 원래 비밀번호를 덮어쓴다. 남의 아이디와 이메일을 아는 사람이 요청하면 원래 주인은 메일을 확인하기 전까지 로그인을 못 한다. 요청 횟수 제한도 아직 없었다.
* 메일 보내기가 요청 트랜잭션 안에서 돈다. 메일 서버가 느리거나 실패하면 DB 저장 확정도 같이 막힌다. 백그라운드 작업이나 대기열로 빼는 걸 다음 할 일로 남겼다.
{% endhint %}

회원 기능 폴더에는 비밀번호 변경만 먼저 넣었고, 내 정보 보기·고치기·탈퇴는 주석으로 "다음에"라고 예고만 했다. 비밀번호 변경 요청에서 지금 비밀번호에는 규칙 검사를 하지 않는다. 임시 비밀번호이거나 규칙이 생기기 전의 약한 비밀번호일 수 있어서다. 새 비밀번호에만 규칙을 적용한다. 비밀번호를 바꿀 때는 DB 담당을 거치지 않고 회원 객체의 값만 바꾸면 저장 확정 때 알아서 UPDATE 가 나간다(JPA 의 변경 감지와 같다). 표시가 이미 꺼져 있으면 다시 쓰지 않아 쓸데없는 UPDATE 를 줄였다.

DB 에는 "비밀번호 바꿔야 함" 칸을 새로 만들었다. 비워 둘 수 없는 칸이지만 처음부터 기본값을 "아니오"로 줬다. 전날 스크립트 주석에 "필수 칸은 기존 회원이 있으면 실패하니 기본값이 필요하다"고 적어 둔 걸 그대로 지킨 것이라 기존 회원이 있어도 문제없다.

### 4. 메일 보내기

아이디 찾기와 비밀번호 찾기가 메일을 보내야 해서 메일 보내는 부분을 만들었다. 5/5 에 정한 방식대로 "메일 보내기" 규격을 하나 두고 구현체를 두 개 붙였다. 개발용은 실제로 보내지 않고 터미널에 구분선과 함께 메일 내용을 찍으며, 보낸 목록을 쌓아 두어 테스트에서 확인할 수 있다. 다른 하나는 Gmail 로 실제 메일을 보낸다(하루 500통 한도라 운영 때는 SES 나 Resend 같은 서비스로 바꿀 예정이라고 적었다). Gmail 용 라이브러리는 실제로 Gmail 을 쓸 때만 불러오게 해서, 개발용만 쓰는 환경에서는 설치하지 않아도 된다.

어느 쪽을 쓸지는 설정 값으로 고른다. Gmail 로 해 놓고 계정 정보를 빠뜨리면 서버가 시작할 때 바로 에러를 낸다. 설정 이름 다섯 개(메일 방식, Gmail 계정, Gmail 앱 비밀번호, 보내는 사람, 화면 주소)를 설정 코드와 예시 파일에 같이 넣고, Gmail 앱 비밀번호 발급 방법을 주석으로 적었다.

메일 제목은 "\[Rekit] 아이디 안내", "\[Rekit] 임시 비밀번호 안내"이고, 본문에는 "임시 비밀번호 사용 중에는 비밀번호 변경 외 다른 기능을 이용할 수 없습니다"라는 안내가 들어간다.

{% hint style="info" %}
**연결 규격에 처음 붙은 실제 구현**

5/5 에 결제·본인인증·문자 인증은 규격만 만들어 두었다. 실제 구현이 붙은 첫 규격이 메일이었고, "설정은 세 곳 같이 고친다"는 규칙도 여기서 처음 적용했다.
{% endhint %}

### 5. 로그인한 사람만 통과시키는 검사 장치

비밀번호 변경 기능만 첫 번째 장치를 쓰고, 나머지 로그인 필요 기능은 전부 두 번째를 쓰기로 정했다. 그래서 임시 비밀번호로 들어온 사람은 비밀번호 변경 말고는 아무것도 할 수 없다. 로그인 연장 응답에도 매번 DB 에 있는 지금 값을 실어 보낸다. 연장과 연장 사이에 누가 임시 비밀번호를 발급했을 수도 있는데, 처음 값으로 굳어 버리면 그걸 놓치기 때문이다.

_근거 커밋: `3ffcea9` · 개발자용: `core/deps.py` 의 `get_current_user`(`HTTPBearer`)·`get_active_user`, 에러 `ACCOUNT_INACTIVE`·`PASSWORD_CHANGE_REQUIRED`_

### 6. 입력 오류 안내를 한국어 문장으로

입력이 틀렸을 때 전체 메시지는 "요청 형식이 올바르지 않습니다"에서 "입력값을 확인해주세요"로 바꿨다. 칸별 오류도 전에는 `VALUE_ERROR` 같은 영어 대문자 코드였는데, 이제 화면에 그대로 띄울 수 있는 한국어 문장이 들어간다. 입력 검사 코드에서 직접 쓴 오류 문장을 그대로 쓰고, 검사 도구(Pydantic)가 앞에 붙이는 "Value error, " 는 떼어 낸다.

다만 최소 글자 수나 정규식 같은 기본 제약은 여전히 영어 문장("String should have at least 8 characters")이 나간다. 한국어로 보이고 싶으면 직접 검사 코드로 옮기라고 서버 명세서에 주의를 적었다.

_근거 커밋: `3ffcea9` · 개발자용: `core/exceptions.py`(`_strip_value_error_prefix()`)_

### 7. 서버 명세서 고치기

새로 생긴 에러 두 개(계정 비활성, 비밀번호 변경 필요)를 에러 목록에 넣고, "출입증 만료"에 "갱신용 출입증을 잘못 쓴 경우"도 포함된다고 적었다. 에러 응답 예시도 실제 모양으로 고쳤다. 아이디 중복 확인 주소 이름을 `check-username` 에서 `check-login-id` 로 바꾸고, 중복이어도 409 에러가 아니라 "쓸 수 없음"으로 답한다고 적었다. 로그인·연장 응답에 출입증 종류와 "비밀번호 바꿔야 함" 칸을 넣었고, 아이디 찾기 응답에서는 가린 아이디와 가입일을 빼고 "보냈음"만 남겼다. 비밀번호 찾기는 "재설정 링크 보내기"에서 "임시 비밀번호 발급"으로 바꾸고 재설정 기능 항목은 지웠다.

{% hint style="warning" %}
**명세서의 응답 모양이 둘로 갈렸다**

5/2 명세서는 성공 응답을 `{ "data": … }` 로 한 번 감싸기로 약속했는데, 이날 로그인 쪽 응답들은 감싸지 않은 모양으로 바뀌었다. 문서 안에 두 방식이 섞이기 시작했다.
{% endhint %}
