### 1. 한글 브랜드명 검색 대응

#### 배경 — 왜 했나

"리키트"와 "리킷트"로 검색해도 사이트가 나오지 않았다. 원인을 진단한 결과:

> 🐞 **원인**
>
> * `<title>`, `description`, `og:site_name`에 영문 **"rekit"만** 있었다. 한글 "리키트"는 푸터 사업자정보의 `상호명: 리키트(REKIT)` 한 곳에만 있었다.
> * "리킷트"는 사이트 어디에도 없었다.
> * 브랜드 구조화 데이터(JSON-LD)가 없었다.
> * **네이버 서치어드바이저에 등록하지 않은 상태**였다. 구글 서치콘솔은 등록한 것으로 기억한다고 함.

> 💡 **배운 점**
>
> 검색엔진은 페이지에 적힌 단어로 문서를 찾는다. "rekit"과 "리키트"를 알아서 같은 이름으로 연결해 주지 않는다. 오타 변형도 페이지에 없으면 걸리지 않는다. 프리렌더는 이미 잘 동작하고 있어서(배포 HTML을 curl로 확인) 기술적인 문제는 아니었다.

#### 한 일

| 파일                                                    | 변경                                                                                                                              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `src/composables/usePageSeo.ts`                       | `SITE_NAME`을 `'리키트 rekit'`으로(og:site\_name), title 접미사 `· 리키트 rekit`, 중복 접미사 판정은 `endsWith('rekit')`                            |

| `todo.md`                                             | SEO 섹션에 완료 항목과 네이버 등록 할 일 추가, 3단계 JSON-LD 중 Organization 완료 표시                                                                  |

> 💡 **JSON-LD를 `index.html`에 넣은 이유**
>
> 모든 페이지에 똑같이 들어가는 사이트 단위 정보라서 정적 HTML에 넣었다. 프리렌더가 이 내용을 그대로 유지한다. 사이트 공통 메타데이터로 관리했다.

#### 검증

* `npm run type-check` 통과
* 빌드와 프리렌더 결과는 직접 확인하지 않았다. 배포 후 운영 HTML의 title과 JSON-LD를 확인하는 명령로 확인할 것.
* 구글 [리치 결과 테스트](https://search.google.com/test/rich-results)로 JSON-LD를 검증하지 않았다.

### 2. 네이버 진단 대응 — 메타 길이 단축

#### 배경 — 왜 했나

`0.3.9`를 배포한 뒤 네이버 서치어드바이저의 "URL 실시간 조회"에서 경고 3종이 나왔다: robots.txt 없음, 사이트 제목 40자 초과, 설명 80자 초과(OG도 같음).

> 💡 **네이버 기준**
>
> 제목 **40자**, 설명 **80자** 이내. 구글보다 훨씬 짧다. 접미사 `· 리키트 rekit`(12자)를 붙이면서 제목이 초과됐다.

#### 한 일

| 대상                                   | 변경                                                               |
| ------------------------------------ | ---------------------------------------------------------------- |
| 홈 (`HomeView.vue`, `index.html`)     | 제목 42자→35자 \`업소용 중고가전 직거래 - 폐업 매장 가전                             |
| `/products` 카테고리 9종 (`ListView.vue`) | 제목을 모두 26\~34자로, 80자 넘던 설명도 단축                                   |
| 소개 (`AboutView.vue`)                 | 제목 `서비스 소개`(`리키트(rekit) 소개 · 리키트 rekit`처럼 겹치던 문제 수정), 설명 92자→58자 |

| 상품 상세 (`DetailView.vue`)             | 제목에서 \`                                                          |

#### 검증

* `type-check` 통과, `npm run build-only`(프리렌더 포함) 성공. 프리렌더 결과 9개 페이지 모두 제목 ≤35자, 설명 ≤72자 확인.

> ⚠️ **"robots.txt 없음" 경고는 코드 문제가 아님 (원인 정정)**
>
> 네이버 [robots.txt 가이드](https://searchadvisor.naver.com/guide/seo-basic-robots)와 대조해 보면 응답은 모두 정상이다: 루트 위치, `200`, `text/plain`(HTML로 응답하면 "없음" 처리될 수 있는데 해당 없음), BOM 없음. http→https **308 한 번은 가이드상 리다이렉트 5회까지 허용**이라 원인이 아니다. 308 응답은 원인이 아님을 확인했다. 등록 직후라 robots.txt 수집 상태가 진단에 반영되지 않았을 가능성을 남은 확인 항목으로 기록했다. 대응은 서치어드바이저 **검증 → robots.txt → 수집 요청**이다. robots.txt가 없어도 "모두 허용"으로 처리되므로 실제 수집에는 영향이 없다.

15:00 에 네이버 소유 확인용 태그를 넣고 0.3.8 로 배포 준비를 했다. 바로 다음 사이트맵을 추가하면서 이미 올린 0.3.8 이름표를 새 코드로 옮기려 했는데, 이미 올린 태그를 변경하지 않는 규칙에 따라 0.3.9 로 새로 붙였다. Jenkins 접근 권한 범위를 확인한 뒤 빌드와 배포를 직접 실행했다.

> 💡 **배운 점 — 진단 통과와 검색 노출은 다르다**
>
> 네이버 "URL 실시간 조회"는 네이버 로봇이 지금 접속해서 본 내용을 진단해 줄 뿐이고, 실제 검색에 실렸는지는 옆의 "URL 검색결과" 쪽에서 본다(16:12·16:18 대화). 이날은 진단만 통과했다. 나흘 뒤 [11.15 일지](https://jineuns-tech.gitbook.io/jineuns-tech-docs/rekit/2026-11/2026-11-15) 에서 "수집은 됐는데 검색에 안 실리는" 이유가 밝혀졌는데, 미리 만들어 둔 HTML 에 서버 에러 화면이 그대로 찍혀 있었기 때문이다.

> 💡 **계획서 수정과 배포 버전**
