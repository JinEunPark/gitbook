### 1. 관리자 화면 공통 틀

관리자 화면들이 같이 쓸 바깥 틀부터 만들었다. PC 에서는 왼쪽 메뉴가 늘 붙어 있고, 화면 폭이 1024px 보다 좁아지면 메뉴가 숨었다가 햄버거 버튼을 누를 때 서랍처럼 나온다. 운영자가 휴대폰으로도 관리자 화면을 볼 수 있게 하려는 것이었다.

왼쪽 메뉴는 폭 240px 이고 스크롤해도 제자리에 있다. 로고와 "ADMIN CONSOLE" 글자 아래에 대시보드, 상품 관리, 주문 관리, 회원 관리, 매출/정산 다섯 메뉴가 있고, 맨 아래에는 로그인한 운영자 이름(정보가 없으면 "운영자")이 나온다. 위쪽 머리에는 화면 제목과 부제, 그리고 화면마다 다른 버튼을 끼워 넣는 자리를 두었다. 서랍 상태에서는 어두운 배경을 누르거나 다른 화면으로 이동하면 메뉴가 저절로 닫힌다.

{% hint style="info" %}
**틀을 앱 전체가 아니라 각 화면 안에서 씌운 이유**

로그인·주문 화면은 앱 맨 바깥(`App.vue`)이 어떤 틀을 쓸지 고른다. 관리자는 반대로 맨 바깥에서 아무 틀도 씌우지 않고, 관리자 화면 하나하나가 공통 틀을 직접 두르면서 자기 제목·부제·버튼을 넣는다. 화면마다 제목과 머리 버튼이 달라서 이렇게 하는 편이 간단했다. Thymeleaf 로 치면 공통 레이아웃에 화면별 `th:fragment` 를 끼우는 방식이다.
{% endhint %}

주소가 `/admin` 으로 시작하면 구매자용 머리·꼬리·하단 탭이 안 보이게 했고, 이걸로 주소별 바깥 틀이 일곱 가지가 됐다.

시안 속 관리자 화면 다섯 개를 실제 화면 크기와 배치에 맞게 옮겼다. 숫자는 모두 화면 코드 안에 적어 둔 가짜 값이고, 상품 목록과 "매출 상위 상품"만 가짜 상품 8개가 든 보관함을 읽어 온다(읽기만 한다).

| 화면      | 주소                | 보이는 내용 (가짜 값)                                                                                                                                                                                                                  |
| ------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| 상품 관리   | `/admin/products` | 검색, 상태 버튼(전체/판매중/품절/비공개, 개수 표시), 상품 표                                                                                                                                                                                          |

### 3. 상품 등록 화면 (`/admin/products/new`, 854줄)

시안 14화면에는 없던 화면이다. 대시보드와 상품 목록에 있는 "상품 등록" 버튼이 갈 곳이 필요해서 새로 설계했다. 운영자가 상품을 올릴 때 등급, 동작 상태, 흠집, 흠집 사진 같은 검수 정보를 빠뜨리지 않도록 칸을 잘게 나눠 놓았고, 버튼은 아직 아무 일도 하지 않는다.

입력 칸은 다섯 묶음이고 오른쪽에 미리보기가 붙어 있다. 각 칸에는 예시 값이 미리 들어 있다.

| 묶음          | 항목                                                                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본 정보       | 상품명(예: 삼성 비스포크 4도어 냉장고), 브랜드, 모델명, 카테고리와 하위 카테고리(4도어), 제조연도, 용량/크기                                                                                                                |
| 상태 등급       | A 상급(외관 거의 새것, 동작 완벽) / B 중급(사용 흔적 약간, 동작 정상) / C 하급(흠집·얼룩 다수, 동작 정상) 중 카드로 고르고, 동작 상태(정상/부분 이상/미작동)와 흠집·손상(없음/경미/있음)을 따로 고른다. 상태 설명 칸(예: "좌측 도어 하단 1cm 미세 스크래치…")과 "동작 보증 필수" 표시 |
| 사진          | 정면(대표), 측면, 내부, 흠집 부위(경고 표시), 빈 칸까지 5칸                                                                                                                                            |
| 가격·재고       | 정가 3,890,000, 판매가 1,290,000 을 넣으면 할인율이 저절로 계산된다(1 − 판매가/정가). 재고                                                                                                                   |
| 배송          | "전문 설치 배송", 배송비 40,000, 설치 지역 "수도권 전 지역"                                                                                                                                          |
| (오른쪽) 공개 설정 | 판매중(바로 공개) / 비공개(임시 저장) / 예약 공개                                                                                                                                                   |
| (오른쪽) 체크리스트 | 기본 정보, 등급, 사진 4장 이상, 판매가, 배송 정보. 입력할 때마다 하나씩 체크된다                                                                                                                                 |

위쪽의 임시저장·취소·등록하기 버튼은 셋 다 아직 동작하지 않는다. 당시 부제는 "새 철거 가전 상품을 등록합니다"였는데, 이 문구는 이틀 뒤 '폐업' 이야기로 바꾸면서 정리했다([05.05 일지](2026-05-05.md)).

{% hint style="success" %}
**검수 정보는 등록 화면에서 강제한다**

5/1 요구사항 정의서에 "상세 사진을 많이 올려 분쟁을 막는다", "동작 보증 상품과 외관/부품용 상품을 구분한다"고 적어 둔 것이 이 화면 구조로 이어졌다. 흠집 사진 칸에 경고 표시를 달고, 동작 상태와 흠집 정도를 따로 고르게 하고, 사진 4장 이상을 체크리스트로 요구했다.
{% endhint %}

### 4. 프로젝트 안내문(CLAUDE.md) 갱신

AI 도구가 읽는 안내문에 관리자 화면이 겉모습뿐이라는 사실과 앞으로 해야 할 관리자 일을 적었다. 주소별 바깥 틀 표에 관리자(`/admin/*`) 줄을 넣고, 만든 것 목록에는 "관리자 6화면, 1024px 미만이면 메뉴가 서랍으로 바뀜, 화면만 있고 권한 검사·등록/수정·실제 CSV 없음, 주문·회원·매출은 화면 안의 가짜 목록 사용"이라고 적었다. 안 만든 것 2번은 "관리자 화면"에서 "관리자 기능"으로 좁혀서 권한 검사(로그인 정보에 아직 역할 칸이 없음), 상품·주문 등록과 수정, 실제 CSV 내보내기, 실제 그래프를 남은 일로 적었다.

{% hint style="warning" %}
**지금은 누구나 `/admin` 에 들어갈 수 있다**

로그인 정보에 일반 회원/관리자 같은 역할 구분이 없고, 주소를 옮길 때 막아 주는 장치(라우터 가드)도 없다. 가짜 데이터 단계라 당장은 괜찮지만 서버와 연결할 때 반드시 막아야 할 구멍이라 안내문에 따로 적어 뒀다.
{% endhint %}
