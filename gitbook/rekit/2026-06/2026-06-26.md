### 1. 가입 화면의 이메일 인증

가입 화면의 이메일 칸 옆에 "인증코드 받기" 버튼을 달았다. 누르면 버튼이 "발송 중"으로 바뀌고, 발송되면 이메일 칸이 잠기면서 버튼에 60초 카운트다운이 돈 뒤 다시 보낼 수 있게 된다. 그 아래에 6자리 코드 입력칸과 "스팸함도 확인해 주세요, 10분간 유효" 안내가 나온다. 코드를 넣어 확인되면 버튼이 "인증 완료"로 바뀌고, 이때부터 가입 버튼이 눌린다. 전에는 이메일 형식만 맞으면 눌렸다.

코드 입력칸에는 숫자 키패드가 뜨게 했고, 메일이나 문자로 온 코드를 휴대폰 키보드 위에 바로 띄워 주는 속성(`autocomplete="one-time-code"`)도 붙였다. 인증한 뒤 이메일을 바꾸면 인증이 처음으로 돌아간다. "확인됨" 증표가 그 이메일에 묶여 있기 때문이다. 서버가 "1분에 한 번만"이라고 거절하면 화면도 60초를 기다리게 맞췄다.

가입 요청에는 이메일 대신 "확인됨" 증표를 보낸다. 서버가 가입과 동시에 로그인 토큰을 주니까, 5/10 에 넣어 둔 "가입 후 같은 아이디로 한 번 더 로그인" 코드는 지웠다. 증표의 15분이 지나 거절되면 "이메일 인증부터 다시 해 주세요"를 띄우고 인증을 초기화한다. 아이디가 이미 쓰이고 있다는 오류가 나도 인증을 초기화해서 다시 인증하게 했다. 증표가 한 번만 쓸 수 있는 건 아닌데도 그렇게 했다.

### 2. 비밀번호 변경 화면

서버에는 5/7 부터 비밀번호 변경 기능이 있었다. 임시 비밀번호로 로그인한 사람은 다른 기능을 부를 때 "비밀번호부터 바꿔야 함" 오류를 받는 장치도 있었는데, 정작 바꿀 화면이 없어서 5/10 화면은 로그인 후 콘솔에 경고만 찍고 있었다. 이날 `/my/password` 화면(482줄)을 만들었다.

칸은 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인 세 개이고 각각 "표시/숨기기"가 있다. 새 비밀번호는 영문과 숫자를 섞어 8자 이상이어야 하고, 현재 비밀번호와 같으면 막고, 확인칸과 일치해야 한다. 현재 비밀번호가 틀리면 "현재 비밀번호가 일치하지 않아요"라고 알려 주고, 성공하면 "내 정보로 돌아가기" 버튼이 있는 완료 화면이 나온다. 임시 비밀번호로 로그인하면 이 화면으로 바로 옮겨지고, 위쪽에 "임시 비밀번호로 로그인하셨어요. 계속 사용하려면 새 비밀번호를 설정해 주세요" 경고가 뜬다. 내 정보 화면의 "비밀번호 변경" 버튼도 이제 이 화면으로 이어진다.

### 3. 장바구니 서버 연결

장바구니를 로그인 여부에 따라 다르게 다루게 했다. 로그인하지 않았을 땐 예전처럼 브라우저 저장소(`rekit.cart.v1`)에 상품 번호, 수량, 선택 여부만 담고, 비면 저장소에서 지운다. 로그인하는 순간 화면이 그걸 알아채고 브라우저에 담긴 항목을 서버에 보내 합치게 한 뒤, 서버가 돌려준 장바구니로 바꾸고 브라우저 저장은 지운다. 로그인한 상태에서 담기·빼기·수량 변경은 화면을 먼저 바꾸고 나서 서버를 부른다. 서버 호출이 실패해도 화면은 그대로 둔다. 로그아웃하면 목록을 비운다. 장바구니 화면에 보이는 상품 정보는 가짜 데이터 대신 서버에서 받는데, 담긴 상품마다 상세 정보를 한 번씩 동시에 부른다.

{% hint style="danger" %}
**화면이 부르는 장바구니 서버 기능 대부분이 실제 서버에 없다**

6/20 에 만든 서버 장바구니와 이날 화면 쪽 장바구니 코드를 맞대 보면 이렇다.

| 화면이 하려는 것    | 실제 서버 (6/20)              | 결과                                                                      |
| ------------ | ------------------------- | ----------------------------------------------------------------------- |
| 장바구니 보기      | 있음                        | 되긴 하는데 합계 이름이 다르다. 화면은 "선택 합계·배송비·예상 합계"를 찾고 서버는 "상품 합계·예상 배송비·총액"으로 준다 |
| 상품 담기(수량 포함) | 있지만 수량 이름이 다름             | 수량이 무시돼 항상 1개로 담긴다                                                      |
| 수량·선택 바꾸기    | 상품 번호가 아니라 장바구니 항목 번호로 찾음 | 엉뚱한 항목을 건드리거나 오류                                                        |
| 하나 빼기        | 위와 같음                     | 위와 같음                                                                   |
| 선택한 것 빼기     | 없음(항목 번호 목록으로 지우는 기능만 있음) | 실패                                                                      |
| 전체 비우기       | 없음                        | 실패                                                                      |
| 로그인 시 합치기    | 없음                        | 실패                                                                      |
| 항목별 "선택" 상태  | 서버 장바구니에 그 칸이 없음          | 저장 안 됨                                                                  |

화면 쪽 호출이 전부 실패해도 조용히 넘어가게 짜여 있고, 화면을 먼저 바꾸기 때문에 겉보기엔 잘 된다. 그런데 로그인 상태에서는 브라우저 저장도 꺼져 있다. 그래서 로그인한 채로 수량을 3개로 바꾸거나 선택을 풀어도, 새로고침하면 서버에 있는 값(수량 1, 선택 정보 없음)으로 돌아간다. 6/22 할 일 목록에 올렸던 "로그인 시 합치기"는 끝내 만들어지지 않았고, 이 노트를 쓰는 11/16 에 서버 코드를 검색해 봐도 장바구니에 합치기·선택 기능은 없다.

이렇게 된 이유도 보인다. 화면 쪽 장바구니 코드는 5/2 에 써 둔 API 설계 문서(`docs/api.md`)의 장바구니 부분과 정확히 같다(직접 대조했다). 반면 6/20 서버는 그 문서가 아니라 항목 번호 기준의 자체 설계로 만들어졌다. 같은 문서를 두 쪽이 다르게 따른 셈이다. 가입·비밀번호는 실제 서버 명세를 받아 확인했지만, 장바구니는 문서만 보고 만든 것으로 보인다(추정).
{% endhint %}
