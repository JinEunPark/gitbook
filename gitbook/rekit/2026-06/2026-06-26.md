# 06.26 · 가입 인증 화면, 장바구니 계약 불일치 발견

## 가입 인증과 비밀번호 변경

가입 화면에 코드 발송, 60초 재발송 대기, 6자리 코드 검증, 10분 유효 안내를 구현했다. 검증 완료 전에는 가입 버튼을 비활성화하고, 이메일을 변경하면 인증 상태를 초기화한다. 가입에는 이메일 대신 확인 JWT를 전달하고, 가입 직후 자동 로그인한다.

`/my/password` 화면에 현재 비밀번호·새 비밀번호·확인 입력을 구현했다. 영문과 숫자를 포함한 8자 이상을 검증하고, 임시 비밀번호 로그인 사용자는 `?required=1`로 이 화면으로 이동시킨다.

{% hint style="warning" %}
**확인된 제약**: 강제 이동은 로그인 직후 한 번만 수행한다. 다른 주소에 직접 접근하면 서버가 비밀번호 변경 필요 오류로 응답한다.
{% endhint %}

## 장바구니 서버 연결

비로그인 상태는 `rekit.cart.v1`에 상품 번호·수량·선택 상태를 저장하고, 로그인하면 서버 장바구니와 합치는 흐름을 구현했다. 로그인 상태의 담기·삭제·수량 변경은 화면을 먼저 변경한 뒤 서버를 호출한다. 상품 정보는 항목별 상세 조회로 가져왔다.

{% hint style="danger" %}
**확인된 계약 불일치**

| 화면 요구                | 서버 제공        | 결과                |
| -------------------- | ------------ | ----------------- |
| 장바구니 보기              | 합계 필드명이 다름   | 일부 표시 불일치         |
| 수량 포함 담기             | 수량 필드명이 다름   | 항상 1개 저장          |
| 수량·선택 변경, 단건 삭제      | 항목 ID 기준 API | 오류 또는 다른 항목 변경 가능 |
| 선택 삭제·전체 비우기·로그인 합치기 | API 없음       | 실패                |
| 항목 선택 상태             | 서버 필드 없음     | 저장되지 않음           |

실패를 무시하고 화면을 먼저 변경하므로 화면에서는 동작해 보이지만, 새로고침하면 서버 값으로 되돌아간다. 화면은 `POST /cart/sync`를 호출하지만 서버에는 없다. 서버 실제 API는 `POST /cart/items {product_id, quantity}`, `PATCH·DELETE /cart/items/{item_id}`, `POST /cart/items/bulk-delete`다.
{% endhint %}
