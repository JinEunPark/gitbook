# 06.23 · 카테고리 DB 로, 상품 목록 첫 연결

카테고리를 DB로 이전하고 관리자용 CRUD를 구현했다. 홈·상품 목록·상세 화면은 서버 상품과 카테고리를 사용하도록 연결했으며, SeaweedFS에 상품 사진을 올리는 스크립트도 추가했다. 작업 시간은 13:05\~14:26이다.

## 카테고리 DB 이전

고정 Enum 카테고리를 `product_categories` 테이블로 옮기고 초기 6개 카테고리를 마이그레이션에 포함했다. `GET /categories`와 `/admin/categories` CRUD를 추가했다. 카테고리 ID는 대문자로 시작하는 영문 값만 받고 중복을 거절한다. 상품의 카테고리는 1\~30자 문자열로 유지했다.

{% hint style="warning" %}
**확인된 제약**: 상품 카테고리에 외래키를 두지 않았다. 존재하지 않는 카테고리로 상품을 저장할 수 있고, 카테고리를 삭제해도 연결된 상품을 검사하지 않는다.
{% endhint %}

## 상품 화면 서버 연결

홈·목록·상세 화면에서 서버 상품을 표시하도록 구현했다. 카테고리는 Pinia에서 한 번만 불러오고, 화면별 ViewModel은 목록·로딩·오류·빈 상태를 제공한다. 목록은 이전 요청 응답을 무시하는 `requestSeq`를 사용한다. 상세는 상품과 관련 상품 4개를 조회하며, 상품 사진이 없거나 로드에 실패하면 기존 아이콘을 표시한다.

{% hint style="warning" %}
**확인된 제약**

* 할인율 정렬과 복수 등급 필터는 서버 지원이 없어 프론트에서 처리한다.
* 목록은 첫 페이지 100개로 고정되어 있고 페이지네이션이 없다.
* 목록 응답에 재고·모델명·연식이 없어 재고는 1, 나머지는 빈 값으로 처리한다.
* 장바구니·관심상품·주문·배송지·관리자 화면은 아직 브라우저 또는 가짜 데이터 기반이다.
{% endhint %}

## 상품 사진 업로드

`upload_images_to_seaweedfs.py`에서 Unsplash 이미지를 받아 `products/` 아래에 업로드하고 DB 사진 행을 다시 생성하도록 구현했다. 대상은 시험용 상품 1~~6번과 테스트 상품 10~~20번이다.

{% hint style="warning" %}
**확인된 제약**: 사진 테이블을 비운 뒤 다시 생성하므로 개발 DB에서만 실행한다.
{% endhint %}
