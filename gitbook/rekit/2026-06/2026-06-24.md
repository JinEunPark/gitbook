## 프로필 수정과 회원탈퇴

`PATCH /users/me`에서 이름(1\~50자)과 하이픈 없는 숫자 형식의 휴대폰 번호를 선택적으로 수정하도록 구현했다. 요청 처리 중 조회한 회원 엔터티를 변경하고 요청 종료 시 저장한다.

`DELETE /users/me`는 회원 행을 삭제하지 않는다. 활성 상태를 해제하고 상태를 `UserStatus.DORMANT`로 변경하며, CI/DI를 삭제하고 `users.withdrawn_at`에 탈퇴 시각을 기록한다. 주문 정보는 보관하고 개인 식별값만 즉시 파기하는 정책으로 구현했다.

{% hint style="warning" %}
**확인된 제약**

* 배송지는 하이픈·공백이 있는 휴대폰 번호를 정규화하지만 프로필 수정은 같은 값을 거절한다.
* 탈퇴 전용 상태가 없어 휴면과 탈퇴를 `withdrawn_at`으로만 구분한다.
* 이메일·로그인 아이디·이름·휴대폰 및 소셜 계정 정보가 남아 재가입과 개인정보 최소화 정책에 문제가 있다.
* refresh 쿠키를 삭제하지 않는다. 이후 요청은 비활성 계정 검증에서 차단된다.
{% endhint %}

_근거: `f0bc59d` · `PATCH /users/me`, `DELETE /users/me`, DB 마이그레이션 `4cfeaf4318f6`_

## 배송 조회와 환불 요청

`GET /orders/{orderNumber}/shipment`로 배송 방식, 상태, 택배사, 송장번호, 발송·도착 시각을 조회하도록 구현했다. 주문 소유자가 아니면 주문 없음으로, 배송 정보가 없으면 배송 정보 없음으로 처리한다.

`POST /orders/{orderNumber}/refund/request`는 배송 완료 주문만 받는다. 요청을 받으면 주문 상태를 즉시 환불됨으로 변경하고 취소 시각을 저장한다. 주문 조회·취소·환불에 중복되던 소유권 검증은 `_get_order_for_user()`로 통합했다.

{% hint style="warning" %}
**확인된 제약**

환불 요청은 관리자 승인, 반품 검수, 수령 후 7일 기한 검증, 결제대행사 취소 없이 주문 상태만 변경한다. 실제 환불과 주문 상태가 달라질 수 있다.
{% endhint %}

_근거: `f0bc59d` · `RefundForbidden`, `ShipmentNotFound`, `REFUND_WINDOW_DAYS`_

## 사진 업로드와 테스트 정리

사진 업로드 스크립트의 저장소 연결을 재사용하고, `_process_one()`을 `asyncio.gather`로 실행했다. `asyncio.Semaphore(5)`로 동시 처리 수는 5건으로 제한했다. 실패한 사진은 건너뛴다.

테스트 13개 파일에 반환 타입을 추가하고 mypy·ruff 규칙(N802·N806, B017, UP017)을 정리했다. `.claude/settings.json`에는 배송지 입력 규칙 테스트 실행 권한이 추가됐다.
