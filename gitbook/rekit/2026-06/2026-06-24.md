### 1. 프로필 수정과 회원탈퇴

마이페이지에서 이름과 휴대폰 번호를 고치는 서버 기능을 만들었다. 둘 다 골라서 보낼 수 있고, 이름은 1\~50자, 휴대폰은 `01012345678` 처럼 하이픈 없는 숫자만 받는다. 고칠 때 DB 를 다시 조회하지 않고, 요청 처리 중에 이미 불러와 있는 회원 객체의 값만 바꾼다. 저장은 요청이 끝날 때 한꺼번에 일어난다. JPA 의 변경 감지(dirty checking)와 같은 원리다.

{% hint style="info" %}
**휴대폰 번호 규칙이 두 가지가 됐다**

6/20 배송지에서는 `010-1234-5678` 처럼 하이픈이나 공백을 넣어도 알아서 빼고 받아 주는데, 프로필에서는 하이픈이 있으면 입력 오류로 거절한다. 같은 휴대폰 번호 입력인데 화면에 따라 규칙이 다르다.
{% endhint %}

회원탈퇴는 회원 정보를 실제로 지우지 않는다. 활성 여부를 끄고, 회원 상태를 6/22 에 만든 "휴면"으로 바꾸고, 본인인증 때 받는 개인 식별값(CI/DI)은 바로 지운 뒤, 새로 만든 "탈퇴 시각" 칸에 지금 시각을 적는다. 코드 주석에 이유가 적혀 있다. 주문 정보는 전자상거래법상 5년 보관 의무가 있어서 지울 수 없고, 개인 식별값은 요구사항 정의서대로 탈퇴 즉시 파기한다는 것이다. 5/2 에 주문이 회원을 참조하는 연결을 "회원 삭제 금지"로 걸어 둔 것도 같은 이유였다. Spring/JPA 에서 흔히 하는 소프트 삭제와 같은 방식이다.

{% hint style="warning" %}
**탈퇴 처리의 빈틈 (당시)**

* 탈퇴 전용 상태를 따로 만들지 않고 휴면으로 표시해서, 관리자 회원 목록에서 휴면 회원과 탈퇴 회원이 구분되지 않는다. 탈퇴 시각 칸으로만 알 수 있다.
* 이메일·로그인 아이디·이름·휴대폰은 그대로 남는다. 그래서 같은 이메일이나 아이디로 다시 가입할 수 없고, 개인정보를 최소한만 보관한다는 원칙과도 거리가 있다.
* 로그인 유지용 쿠키(refresh)를 없애지 않는다. 다음 요청에서 "활성 아님"으로 막히기는 한다.
* 카카오·네이버·구글로 연결된 소셜 계정 정보도 그대로 남는다.
{% endhint %}

### 2. 배송 조회와 환불 요청

구매자가 자기 주문의 배송 상황을 볼 수 있게 했다. 배송 방식, 상태, 택배사, 송장번호, 발송·도착 시각을 돌려준다. 남의 주문 번호를 넣으면 "주문 없음"으로 답하고, 아직 송장이 안 들어간 주문이면 "배송 정보 없음"으로 답한다. 배송 정보만 읽어 오는 조회를 따로 만들어서 주문 상품 목록은 읽지 않는다.

환불 요청은 배송완료 상태의 주문에만 받고, 그 외 상태면 "환불 불가"로 거절한다. 받으면 곧바로 주문을 "환불됨"으로 바꾸고 취소 시각을 남긴다. 코드에도 "첫 버전: 결제대행사 취소 없이 상태만 변경"이라고 적혀 있다. 그 김에 주문 조회·취소·환불 세 곳에서 반복되던 "내 주문이 맞는지" 확인을 함수 하나로 합쳤다.

{% hint style="warning" %}
**"환불 요청"이 곧 "환불 완료"다**

구매자가 버튼을 한 번 누르면 관리자 확인 없이 주문이 환불됨으로 바뀐다. 상품을 돌려받아 검수하는 단계도 없고, 6/20 에 "수령 후 7일"로 정해 둔 환불 기한도 검사하지 않는다. 원래 할 일 목록에는 "첨부 사진 확인, 상태를 환불요청으로"라고 적혀 있었는데, 환불요청이라는 중간 상태 없이 만들어졌다. 결제대행사를 부르지 않으니 돈은 실제로 돌아가지 않고 주문 상태만 어긋나게 된다.
{% endhint %}

### 3. 사진 올리기 스크립트 속도 개선

6/23 스크립트는 사진 한 장마다 저장소 연결을 새로 열고, 받기와 올리기를 한 장씩 차례로 했다. 이번에 저장소 연결은 한 번만 열어 같이 쓰고, 사진 한 장 처리를 함수로 떼어 여러 장을 동시에 돌리게 했다. 대신 동시에 도는 건 5장까지로 묶었다. 코드 주석에는 무료 사진 사이트와 사진 저장소에 부담을 주지 않으려고 그랬다고 적혀 있다. 실패한 사진은 건너뛴다. Java 로 치면 스레드 5개짜리 풀에 작업을 넣고 한꺼번에 기다리는 것과 같은 효과를, 파이썬의 비동기 처리로 낸 것이다.

### 4. 테스트 코드 정리

테스트 코드 전체에 타입 검사기(mypy)가 요구하는 반환 타입 표시를 붙이고, 테스트용 가짜 서비스의 입력 타입을 채우고, 코드 검사기(ruff)가 잡은 오류를 한꺼번에 고쳤다. 고친 규칙은 함수·변수 이름을 밑줄 소문자로 쓰기(N802·N806), `Exception` 처럼 너무 넓은 오류를 기대하는 테스트 금지(B017), 옛 표준시 표기를 새 표기로 바꾸기(UP017)다. 테스트 파일 13개가 바뀌었는데, 주문·회원 쪽에 새로 넣은 테스트를 빼면 내용은 그대로다. 이날 만든 DB 변경 스크립트도 기존 파일들과 달리 새 타입 표기 방식으로 썼다. 남은 파일 3개는 20분쯤 뒤 두 번째 저장에서 마저 고쳤다.

{% hint style="info" %}
**Claude Code 권한 설정 파일이 처음 저장소에 들어갔다**

두 번째 저장에 Claude Code 설정 파일(`.claude/settings.json`)이 같이 올라갔다. 배송지 입력 규칙 테스트를 매번 묻지 않고 돌려도 된다는 허용 한 줄이 들어 있다. Claude Code 에게 특정 테스트 실행 권한을 준 흔적이 저장소에 남은 첫 사례다.
{% endhint %}
