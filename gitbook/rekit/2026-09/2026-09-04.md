# 09.04 · 취소·환불 결제 연결, 웹훅 금액 검증

## 취소·환불 처리

결제된 주문을 취소하거나 환불할 때 토스 취소 API를 먼저 호출하고, 성공한 경우에만 재고와 주문 상태를 갱신하도록 변경했다. 구매자 취소, 배송 완료 주문의 환불, 관리자 취소가 이 흐름을 사용한다. 취소 요청에는 고유 키를 부여해 네트워크 재시도에도 한 번만 취소되도록 했다.

가상계좌는 입금 대기 상태를 결제완료로 처리하지 않기 위해 받지 않기로 결정했다. 부분취소 API는 구현했지만 주문 및 관리자 화면은 전액 취소만 호출한다.

취소·환불 관련 테스트 18개와 웹훅 금액 검증 테스트 2개를 추가했다. 당시 서버 테스트 결과는 505개 통과와 검사 오류 0건이다.

## 웹훅 검증과 운영 설정

`PAYMENT_STATUS_CHANGED` 웹훅을 등록하고, 수신 시 토스에 다시 조회한 금액과 주문 결제 금액이 같을 때만 결제완료로 갱신했다. 불일치하면 상태를 변경하지 않고 기록만 남긴 뒤 200으로 응답한다. 재전송을 피하기 위한 처리다.

토스 비밀 키를 필수 설정으로 변경했다. 키가 없으면 서버가 시작하지 않도록 해 결제 요청 시 조용히 실패하는 상태를 막았다. 운영 웹훅 주소와 결제창 허용 도메인도 등록했다.

## 검색과 배포

홈·목록·상세의 제목과 설명을 `업소용 중고가전` 중심으로 바꾸고, 카테고리 7개의 제목과 설명을 분리했다. 카테고리별 고정 주소와 사이트맵 반영은 후속 작업으로 남겼다.

배포는 커밋 해시와 `latest` 대신 `0.0.1` 같은 버전 번호로 선택하도록 변경했다. `0.0.2`로 배포 후 `0.0.1`로 되돌리는 절차도 점검했다. Jenkins 컨테이너의 localhost와 호스트 Docker 네트워크가 달라 이미지 확인 단계가 실패해 해당 단계를 제거하고, 애플리케이션 컨테이너에서 상태를 확인하도록 수정했다.

## 확인된 제약과 후속 작업

* 환불 후 취소 웹훅이 오면 환불 상태가 취소로 바뀌고 재고가 복구될 가능성이 있다. 웹훅 중복 방지에 환불 상태를 포함해야 한다.
* 토스 취소 성공 후 DB 저장이 실패하는 경우를 별도로 보정하지 않는다.
* 웹훅은 토스 재조회와 잠금을 같은 요청에서 수행하므로 10초 제한을 넘길 경우 비동기 처리로 분리해야 한다.
* 9월 5일 수동 결제·검색 노출 테스트 결과는 저장 기록에 없다.
