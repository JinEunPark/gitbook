# 09.03 · 토스 결제 위젯 연결

토스 결제 위젯을 주문서에 연결하고 결제 성공·실패 화면을 추가했다. 결제 금액은 화면 계산값, 서버가 다시 계산한 값, 승인 시 DB 주문 금액 순으로 세 번 대조하도록 구성했다. 결제창에는 공개 키만 사용하고, 승인은 비밀 키를 가진 서버가 처리한다.

## 구현

주문서를 로드한 뒤 토스 결제수단과 약관 UI를 표시했다. `결제하기`를 누르면 주문을 만들고 결제 준비 API에서 서버가 계산한 최종 금액을 받아 결제창에 적용한다. 승인에 성공한 뒤에만 장바구니를 비우도록 변경했다.

성공 화면에서는 결제 번호·주문 번호·금액을 받아 승인 API를 호출한다. 결과가 불확실하면 주문 내역으로 이동할 수 있는 안내를 표시한다. 실패 화면은 사용자 취소와 오류를 구분해 보여 준다. 완료 화면에는 승인 결과의 카드 정보와 할부 정보를 표시한다.

결제 요청에는 `RK-YYMMDDNNNN` 주문 번호, 첫 상품명과 `외 N건`, 고객 정보와 선택한 결제수단을 전달했다. 토스가 허용하는 결제수단은 카드·계좌·토스페이·네이버페이·카카오페이로 정규화했다.

## 서버 연동

웹훅은 요청 본문을 신뢰하지 않고 토스 API에 다시 조회한 결과로 상태를 반영한다. 준비·진행 중·입금 대기는 기록만 남기고, 완료 상태가 아닌 승인 결과는 거절한다. 웹훅 4건과 토스 어댑터 3건의 테스트를 추가했으며, 당시 서버 테스트 결과는 483개 통과와 검사 오류 0건이었다. 화면 자동 테스트는 추가하지 않았다.

API 문서의 웹훅 경로를 `/payments/webhooks/toss`로 정리하고, 결제 개발 현황과 실연동 작업 안내 문서를 작성했다.

## 로컬 결제 테스트

개발 서버에서 결제 준비와 승인 요청만 토스 테스트 환경으로 중계하도록 구성했다. 이 중계는 개발 서버에서만 실행하며 서비스 빌드에는 포함하지 않는다. 토스 오류는 결과 확인 중(502), 결제 거절은 토스 오류 코드와 메시지(422)로 변환했다.

## 확인된 제약과 후속 작업

* 결제창을 취소하면 결제대기 주문이 남아 재고 1개 상품을 즉시 다시 주문할 수 없다. 이 문제는 [10.16 일지](../2026-10/2026-10-16.md)에서 처리했다.
* 카드사 코드를 화면용 이름으로 변환하지 않아 완료 화면과 결제 메일에 숫자 코드가 표시될 수 있다.
* 실제 운영 반영 기록과 수동 결제 테스트 결과는 이 날짜의 기록에 없다.
