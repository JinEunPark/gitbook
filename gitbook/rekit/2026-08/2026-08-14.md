# 08.14 · 나이스페이 철회, 토스로 확정

## 작업 요약

결제대행사는 토스페이먼츠로 유지하기로 결정했다. 나이스페이 전환 계획서는 삭제했고, 실제 코드에는 반영하지 않았다. Octomo 휴대폰 인증 작업 뒤에는 운영자가 직접 처리해야 하는 후속 조치 6건도 정리했다.

| 2 | 직접 처리할 후속 조치 6건을 할 일 목록 상단에 기록      | 백엔드 문서 | `03f6132` |

## 결제대행사 결정

7월에 작성했던 나이스페이 전환 계획을 철회하고 토스페이먼츠를 유지했다. 나이스페이 관련 작업은 계획서 단계에만 있었고, 제품 코드에는 반영하지 않았다.

결제 수단은 프로젝트 진행 중 여러 번 검토했다. 5월에는 토스를 검토했고, 6월에는 토스 카드 결제 흐름을 구현했다. 7월에는 PortOne v2와 무통장입금을 함께 검토한 뒤 나이스페이 전환 계획을 작성했다. 이번 결정으로 토스페이먼츠를 기준으로 결제 작업을 이어 갔고, 결제위젯은 9월 3일에 프론트엔드에 연결했다. [09.03 일지](../2026-09/2026-09-03.md)

작업 도중 결제 게이트웨이 연결 계층 파일을 다른 세션과 동시에 수정해 서버 import 오류가 발생한 적이 있다. 변경을 원복해 서버 기동 상태를 복구했고, 이후 동시 작업 시 최신 변경을 먼저 반영하도록 후속 조치에 남겼다.

_근거 커밋: `aee2ffc` · 삭제한 `docs/nicepay_migration.md`_

## 외부 확인이 필요한 후속 조치

Octomo 전환과 전화번호 형식 통일, 자동 품절 작업 뒤에 외부 서비스 설정, 키 발급, 배포처럼 코드만으로 끝낼 수 없는 작업을 정리했다.

| # | 항목               | 처리 내용                                  | 이후 상태                         |
| - | ---------------- | -------------------------------------- | ----------------------------- |
| 1 | Octomo API 키 재발급 | 로컬 권한 설정 파일에 실제 API 키가 남아 있어 새 키 발급 필요 | 8월 28일 설정에서 제거, 11월 5일 재발급 확인 |
| 2 | 토스 실제 키 발급       | FakePG만 사용 중이어서 실제 토스 키 발급 필요          | 11월 16일 기준 미완료                |
| 3 | DB 변경 반영         | 8월 13일 DB 변경을 개발 DB에만 적용               | 당시 테스트·운영 배포 환경 없음            |
| 4 | 기존 전화번호 정규화      | 회원·배송지·주문 테이블의 하이픈 없는 값 정리             | 우선순위 낮음                       |
| 5 | Octomo 실제 흐름 검증  | QR 발급, 문자 전송, 수신 확인, 주문 진입까지 확인        | 후속 검증 필요                      |
| 6 | 동시 작업 충돌 방지      | 여러 세션이 같은 파일을 수정할 때 최신 변경 반영           | 작업 규칙으로 기록                    |

Octomo 어댑터에서는 성공 응답 201 처리와 인증 성공 뒤 코드 삭제를 구현하고 테스트했다. 실제 휴대폰으로 QR을 스캔해 전체 흐름을 검증한 기록은 남기지 못했다.

API 키의 일부 문자열이 할 일 목록에 기록된 문제도 확인했다. 11월에 키를 재발급해 기존 키는 폐기했고, 이후 문서와 커밋 메시지에는 키 값 대신 키 이름만 기록하기로 했다.
