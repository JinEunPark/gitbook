## 결제 승인 실패 처리

토스가 승인을 거절할 때 상태 코드만 남기던 처리를 수정했다. 기존 오류 변환 함수를 적용해 토스 오류 코드와 메시지를 함께 반환했고, 승인 요청에는 `confirm-결제번호` 형식의 중복 방지 키를 추가했다.

토스가 명시적으로 거절한 결제는 실패 상태와 사유를 기록하도록 구현했다. 네트워크 오류처럼 승인 결과를 확정할 수 없는 경우에는 상태를 변경하지 않고 재시도할 수 있게 했다. 오류 코드 전달, 중복 방지 키, 실패 상태·사유 기록을 검증하는 테스트를 추가했다.

{% hint style="warning" %}
### 확인된 제약: 실패 기록 롤백

요청 단위 DB 트랜잭션에서 실패 상태를 저장한 뒤 예외를 다시 발생시키므로, 트랜잭션이 롤백되면 실패 상태와 사유도 함께 롤백된다. 실제 DB에서 거절된 결제가 결제 준비 상태로 남을 수 있다. 단위 테스트는 롤백이 없는 저장소를 사용해 이 문제를 검증하지 못한다.

**후속 작업:** 실패 이력을 별도 트랜잭션으로 저장하거나, 예외 대신 실패 응답을 반환하는 방식으로 분리한다.

## 카테고리 대표 이미지

홈 화면 카테고리는 코드에 고정된 아이콘만 표시하고 있었고, 관리자 화면도 아이콘 이름을 텍스트로 입력하는 방식이었다. 카테고리별 대표 이미지를 등록해 홈 화면에 노출할 수 있도록 변경했다.

카테고리 테이블에 이미지 URL을 추가했고, 공개 카테고리 목록 응답에도 포함했다. 이미지가 없을 때만 기존 아이콘을 사용한다. 관리자 화면에서는 이미지 중심으로 표시하고, 숫자 입력 대신 드래그로 순서를 변경하도록 바꿨다. 순서 변경이 실패하면 화면 상태를 이전 값으로 복구한다.

관리자 수정 요청에서 제목·아이콘·순서를 비우는 요청은 422로 거절하도록 했다. 값이 누락된 경우에만 기존 값을 유지한다. 이를 통해 빈 아이콘으로 응답 생성 중 500이 발생하던 문제와 순서 0을 누락으로 처리하던 문제를 수정했다.

환경별 이미지 URL은 서로 달라 자동 동기화하지 않고, 각 환경에서 관리자가 업로드하기로 했다.

## SVG 업로드 보안

카테고리 이미지에 SVG 지원을 추가하는 과정에서 다음 문제를 재현했다.

* 로그인 없이 업로드 URL을 발급받을 수 있었다.
* 업로드 완료 확인을 호출하지 않아도 파일이 공개 URL로 노출됐다.
* 완료 확인에만 있던 SVG 검사는 우회할 수 있었다.
* SVG 애니메이션과 제어문자가 포함된 `javascript:` 링크를 이용해 검사 우회 가능성이 있었다.

업로드 URL 발급, 업로드 완료 확인, SVG 업로드 세 기능을 관리자 전용으로 제한했다. SVG는 브라우저가 저장소로 직접 전송하지 않고 서버가 파일을 받아 검사한 뒤 저장하도록 분리했다. 크기 제한 초과는 413, 안전하지 않은 SVG는 422로 거절한다.

검사기는 XML을 안전하게 파싱하고, 스크립트·이벤트 속성·`javascript:` 링크·외부 문서 삽입 태그·SVG 애니메이션 태그를 차단한다. 링크 값은 공백과 제어문자를 제거한 뒤 검사하며, 최상위 `svg` 요소가 아니거나 파싱에 실패하면 저장하지 않는다. 업로드 기능 네 가지의 비인증 401 응답과 관리자 권한 검사를 테스트로 추가했다.

{% hint style="warning" %}
### 후속 작업: 저장소 도메인 분리

사진 저장소가 사이트와 같은 도메인의 `/s3/` 경로에 있다. 관리자 제한과 사전 검사를 적용했지만, 이미지 전용 도메인으로 분리하는 작업이 추가로 필요하다.
{% endhint %}
