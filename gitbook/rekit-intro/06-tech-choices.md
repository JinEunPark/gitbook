# 기술 선택 이유

{% hint style="info" %}
**핵심 — 대부분의 선택은 "서버 1대에 같이 올라간다"와 "이미 있던 것을 쓴다"는 두 조건에서 나왔다.**
{% endhint %}

이 표에는 일지 · 커밋 · 설정 주석에 이유가 남아 있는 항목만 넣었다. 언어와 프레임워크(Python · FastAPI · Vue)처럼 선택 이유가 기록에 없는 항목은 넣지 않았다.

## 저장

| 무엇에 | 무엇을 | 왜 |
| --- | --- | --- |
| 주문 · 재고 · 결제 | PostgreSQL 15 | 재고 1개짜리 상품을 행 잠금(`FOR UPDATE`)과 `SKIP LOCKED` 로 판정해야 한다 |
| 몇 분 뒤 사라져도 되는 값 (인증 코드 · 잠금) | Redis 7 | 만료 시간이 있는 임시 값을 DB 표 없이 둔다 (06.25 이메일 인증 코드가 첫 사용) |
| 상품 사진 | SeaweedFS (S3 호환) | 서버에 이미 떠 있던 것을 그대로 썼다 (08.23, 중복 기동 방지). S3 API 라 presigned URL 로 브라우저가 직접 올린다 |
| 쿼리별 통계 | `pg_stat_statements` | 부하테스트 때 어떤 쿼리가 느린지 보려면 호출 수 · 평균 시간이 필요하다 (11.10) |

## 실행

| 무엇에 | 무엇을 | 왜 |
| --- | --- | --- |
| 앱 프로세스 | gunicorn + uvicorn 워커 4개 | Python 프로세스 하나는 GIL 때문에 사실상 코어 하나만 쓴다 → 4코어에 워커 4개 (11.05) |

| 배포 | Jenkins + 서버 안 registry | 같은 서버 안에서 빌드 · 보관 · 실행이 끝나 외부 이미지 저장소 계정이 필요 없다 (08.23) |
| 컨테이너 설정 | Docker Compose | 포트 바인딩과 망 연결을 파일 하나로 관리하고, 태그 시점 파일을 꺼내 롤백한다 |

## 관측

| 무엇에 | 무엇을 | 왜 |
| --- | --- | --- |
| 로그 형식 | structlog JSON | 한 줄이 한 사건이라 `grep` 과 수집기가 그대로 읽고, contextvars 의 `request_id` 를 자동으로 붙인다 |
| 메트릭 | Prometheus (pull) | 앱은 현재 값만 내놓고 수집은 Prometheus 가 한다. k6 결과도 remote write 로 같은 곳에 넣어 서버 지표와 한 시간축에서 본다 |
| 메트릭 기록 위치 | 로그와 같은 미들웨어 | 계측 라이브러리는 라우트 이름을 자체 방식으로 찾아, 로그에서 겪은 중첩 라우터 `/api/v1` 누락이 메트릭에서 재발할 수 있다. 이미 검증된 미들웨어에서 로그와 같은 경로 · 상태 코드로 기록한다 (`dd0adea`) |
| 대시보드 | Grafana | Prometheus 만 조회해 DB 비밀번호가 필요 없다. 계획 중인 Loki 도 같은 화면에 붙는다 |
| 로그 저장 (계획) | Loki + Alloy | ELK 는 JVM 으로 최소 수 GB, Loki 는 수백 MB — 쇼핑몰과 같은 서버다. Promtail 은 지원 종료라 후속인 Alloy (11.10) |
| 로그 검색 대신 포기한 것 | 본문 전문 색인 | Loki 는 라벨만 색인한다. 상품 7개 규모에서는 `grep` 수준 검색으로 충분하다고 판단 (11.10) |
| 오류 추적 (계획) | Sentry 무료 플랜 | 코드 연동은 끝났고 키 발급만 남았다. 개인정보 필드는 보내기 전에 지운다 |
