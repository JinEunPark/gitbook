# 요구사항과 제약

**핵심 — 서버 1대, 운영자 1명, 실제 돈이 오가는 결제. 이 세 가지 제약이 이후 설계의 대부분을 정했다.**

## 무엇을 해야 하는가 — 기능 요구사항

rekit 은 협력업체 매물을 올려 두고, 주문이 확정되는 순간 rekit 이 미리 정한 값에 사들여 rekit 이름으로 판다(10.23 결정). 개인끼리 거래하는 중개 서비스가 아니라서, 결제·환불 책임이 rekit 한 곳에 모인다.

| 영역 | 기능 |
| --- | --- |
| 구매자 | 상품 · 검색 · 장바구니 · 찜 · 배송지 · 주문 · 결제 · 취소/환불 · 문의 |
| 인증 | 이메일 인증 가입 · 소셜 로그인 3사 · 휴대폰 확인(Octomo) · 탈퇴 익명화 |
| 관리자 | 대시보드 · 상품/카테고리 · 주문 · 회원 · 매출 · 고객센터 |

| API 경로 | 도메인 모듈 | 테스트 파일 | DB 변경 스크립트 | 배포 태그 |
| --- | --- | --- | --- | --- |
| 97개 | 11개 | 61개 | 24개 | 0.0.1 ~ 0.0.7 |

_2026-11-17 백엔드 저장소 기준. API 경로는 라우터 데코레이터 수._

## 어느 수준이어야 하는가 — 서비스 수준 목표 (SLO)

"CPU 80%" 같은 자원 기준이 아니라 사용자가 겪는 결과를 기준으로 목표를 정했다. 혼자 운영하면 알림 하나하나가 곧 작업이라, 사용자에게 영향이 있을 때만 울려야 한다.

| SLI | 목표 (30일) | 오류 예산 |
| --- | --- | --- |
| 가용성 — 5xx 가 아닌 응답 비율 | ≥ 99.5% | 요청 10만 건당 500건 |
| 조회 API 지연 — 300ms 안에 끝난 비율 | ≥ 95% | 5% |
| 결제 승인 지연 — 1초 안에 끝난 비율 | ≥ 95% | 5% |
| 결제 성공률 — 토스 명시적 거절 제외 | ≥ 99% | 1% |
| 가동률 — 앱 메트릭 수집 성공 시간 비율 | ≥ 99.5% | 30일 중 약 3시간 36분 |

_근거: 저장소 `docs/slo.md`. 측정 지점이 앱 서버라 nginx·네트워크 구간은 빠진다 — 사용자 체감은 이보다 조금 나쁘다._

## 제약과 그 영향

| 제약 | 사실 | 설계에 준 영향 |
| --- | --- | --- |
| **서버 1대** | 4코어 · 메모리 15GiB · 디스크 98GB 에 컨테이너 16개 안팎 | 서버가 멈추면 쇼핑몰·DB·감시가 같이 멈춘다 → 서버 밖 감시와 백업이 남은 과제 1순위 |
| | | 부하테스트는 운영 서버에서 하지 않는다 (DB·앱·nginx 가 같이 있다) |
| | | 로그 저장소는 JVM 기반 ELK 대신 수백 MB 로 도는 Loki 로 정했다 |
| **운영자 1명** | 개발·배포·장애 대응을 한 사람이 한다 | 알림은 자원 기준이 아니라 SLO 기준, 같은 원인의 알림은 하나로 묶는다 |
| | | 배포는 "태그 하나 고르기", 롤백은 "이전 태그 고르기"로 같은 동작이다 |
| | | 운영 서버 변경은 레포 밖이라 git 기록이 없다 → 변경마다 백업 파일과 일지로 남긴다 |
| **실제 돈이 오가는 결제** | 토스페이먼츠 카드 결제, 취소·환불 시 실제 카드 취소 | 같은 승인 요청이 두 번 가지 않도록 Idempotency-Key 를 쓴다 |
| | | 웹훅 본문은 믿지 않고 토스 결제 조회로 다시 확인한다 |
| | | "거절"과 "결과 모름"을 나눠, 결과를 모를 때는 재결제를 권하지 않는다 |
| **재고 1개짜리 상품** | 중고 설비라 같은 물건이 하나뿐이다 | 재고 차감은 주문과 같은 트랜잭션에서 행 잠금으로 한다 (나중에 따로 처리하면 두 번 팔릴 수 있다) |
| **이미 떠 있던 서버** | nginx 와 SeaweedFS 가 먼저 세팅돼 있었다 | 새로 띄우지 않고 그 위에 얹었다 → 그 두 설정은 앱 레포 밖에 있다 |
| **공유기 뒤 네트워크** | 공유기가 바깥 요청을 서버로 넘긴다 | 공유기 포트 전달도 공개 범위의 일부다 → 서버 쪽 바인딩과 함께 관리해야 한다 |
| **개인정보** | 이름 · 전화번호 · 이메일 · 주소 | 로그에서 민감 필드를 가리고, 탈퇴 시 개인정보를 알아볼 수 없게 바꾼다 |
| **비용** | `[확인 필요: 월 비용 상한 — 기록 없음]` | 외부 이미지 저장소 없이 서버 안 registry, 관측 도구는 직접 띄움, Sentry 는 무료 플랜 계획 |
